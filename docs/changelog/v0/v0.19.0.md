# llm-translator v0.19.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 0.19.0 runs Anthropic's server tools (`web_search`, `web_fetch`, `code_execution` and `tool_search`) in the translator, so a model behind any converted upstream can use them. Before this release those tools were dropped. Now, when an executor is configured for a tool type, the translator offers the tool to the upstream as a function, runs each call itself and returns Anthropic's own `server_tool_use` and result blocks. Web search answers also carry `web_search_result_location` citations.

Existing setups keep working. No executor is on by default: without `serverTools`, server tools are dropped as before. Requests to an Anthropic-protocol upstream pass through untouched. Nothing adds a dependency. None of this has been run against real clients and providers yet; real-backend checks are tracked in [#62](https://github.com/CLDMV/llm-translator/issues/62).

## ✨ Features

### Server tool runner ([#209](https://github.com/CLDMV/llm-translator/pull/209))

The new `serverTools` config key (also a `send` option) takes a list of executors, one per tool type. For each server tool that has an executor, the runner:

- offers the tool to the upstream as an ordinary function, with the input schema the executor gives;
- runs the model's calls and appends each call and its result to the conversation;
- asks the upstream again, until the model stops calling server tools.

The client gets `server_tool_use` blocks (`srvtoolu_` ids), the result blocks and the model's answer. `usage` is summed over every upstream call, and `usage.server_tool_use` counts web search and web fetch requests.

- **Limits.** `max_uses` applies per request. A request makes at most `maxRounds` upstream calls (10 by default); a request that hits the cap ends with `stop_reason: "pause_turn"`, and the client continues it the way it would with Anthropic.
- **Mixed turns.** A turn that calls server tools and client tools runs the server tools, then ends with `stop_reason: "tool_use"` so the client can answer its own calls.
- **History.** `server_tool_use` and result blocks in the history are replayed to the upstream as function calls and results.
- **Coverage.** The runner sits above the converters, so it serves every converted upstream. Streaming is supported.

You can write your own executors. The ones below ship with the library. See [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#servertools-not-a-converter-setting). Resolves [#5](https://github.com/CLDMV/llm-translator/issues/5).

### Web search ([#210](https://github.com/CLDMV/llm-translator/pull/210))

`webSearch({ provider })` serves `web_search_*` through a search provider adapter, and `searxng({ url })` is the reference adapter for a SearXNG instance.

- **Domains.** `allowed_domains` and `blocked_domains` filter the results, matching subdomains and optional paths.
- **Location.** `user_location` is passed to the adapter.
- **Results.** They come back as `web_search_tool_result` blocks. When the conversation is replayed, the upstream model reads them again.

See [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#web-search-websearch-and-searxng). Resolves [#10](https://github.com/CLDMV/llm-translator/issues/10).

### Web search citations ([#217](https://github.com/CLDMV/llm-translator/pull/217))

Search results are numbered across the whole request, and the model is asked to write `[[cite:N]]` after any statement that comes from result N. The translator removes those markers and splits the cited text into its own text block. Each such block carries a `web_search_result_location` citation with `url`, `title`, `encrypted_index` and `cited_text`.

- **Streaming.** A stream carries the citations as `citations_delta` events.
- **Replay.** When the client sends the conversation back, the citations are dropped for the upstream and the results keep their numbers.
- **Custom executors.** An executor of your own gets the same behavior by adding a `cite(item)` function.

Resolves [#216](https://github.com/CLDMV/llm-translator/issues/216).

### Web fetch ([#212](https://github.com/CLDMV/llm-translator/pull/212))

`webFetch({ allow })` serves `web_fetch_*` through the same fetcher as `documentUrls`, with the same SSRF protections. Every resolved address must be public, connections are pinned, and each redirect is checked again.

- **Which URLs.** As on Anthropic, a URL must already appear in the conversation. `allowed_domains` and `blocked_domains` narrow the host allow-list per request.
- **Content.** HTML becomes readable text through a single forward scan with no backtracking patterns. PDFs go through the PDF reader page by page.
- **Tool options.** `max_content_tokens` and `citations` are honored.

See [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#web-fetch-webfetch). Resolves [#11](https://github.com/CLDMV/llm-translator/issues/11).

### Code execution ([#213](https://github.com/CLDMV/llm-translator/pull/213))

`codeExecution({ sandbox })` serves `code_execution_*` through a sandbox adapter that you provide. The library never starts a process itself.

- **Tool versions.** `code_execution_20250522` runs Python. Later versions run bash, and also get the `text_editor_code_execution` tool (`view`, `create` and `str_replace`) when the adapter supports files.
- **Containers.** Container ids go back and forth, so a client can reuse its sandbox across requests.
- **Output files.** Files the sandbox writes are stored in the Files API store and are downloadable from either front, as Anthropic allows for tool-created files. Uploaded files stay non-downloadable on the Anthropic front.

See [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#code-execution-codeexecution). Resolves [#12](https://github.com/CLDMV/llm-translator/issues/12).

### Tool search ([#215](https://github.com/CLDMV/llm-translator/pull/215))

`toolSearch()` serves `tool_search_tool_regex_*` and `tool_search_tool_bm25_*`. Tools marked `defer_loading: true` are kept out of the upstream request until a search returns them in its `tool_references`, in the same request or in a later one.

- **Regex search.** Patterns run with a time limit.
- **BM25 search.** Tools are scored on their name, description and argument text.

See [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#tool-search-toolsearch). Resolves [#208](https://github.com/CLDMV/llm-translator/issues/208).

## Upgrade notes

- No breaking changes.
- Server tools stay off until you add executors to `serverTools`. Without them, `web_search_*`, `web_fetch_*`, `code_execution_*` and `tool_search_*` tools are dropped as before.
- The web fetch executor needs an `allow` list. The code execution executor needs a sandbox you run yourself. Run model-chosen code only somewhere it can't reach anything you care about.
- On the Anthropic front, `GET /v1/files/{id}/content` now serves files that code execution created. Uploaded files are still refused with `not_downloadable`, as on Anthropic.
