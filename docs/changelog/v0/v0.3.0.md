# llm-translator v0.3.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 0.3.0 makes the translator usable as the metering and access-control layer of an app that serves several users. `send()` now reports the final token usage of every request, a new `route()` leaf says where a request would go before it is sent, and the server takes an `authorize(request)` hook and an `onUsage(report, context)` callback so an app with its own key system no longer has to rebuild the routes. The whole release landed as one pull request, [#78](https://github.com/CLDMV/llm-translator/pull/78), which covers usage reporting ([#76](https://github.com/CLDMV/llm-translator/issues/76)) and the authorize hook ([#77](https://github.com/CLDMV/llm-translator/issues/77)).

## ✨ Features

### Final usage from `send()` ([#76](https://github.com/CLDMV/llm-translator/issues/76), [#78](https://github.com/CLDMV/llm-translator/pull/78))

Every reply from `send`, error replies included, has a non-enumerable `usage` property: a promise of one normalized report that never rejects. `send(body, { onUsage })` receives the same report exactly once, also when `send` throws because the caller aborted. For JSON and error replies the report is ready when `send` returns. For a stream it is delivered when the stream ends, fails or is stopped early (`break` or `return()`), and a stream nobody iterates never settles. The stream itself is passed through unchanged, so `api.sse.write` works as before, and an exception in `onUsage` is reported as a warning and never breaks the reply.

The report is `{ input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens, reported, complete, reason, model, requested, upstream, front, stream }`:

- The four token fields are numbers or `null`. Unknown is never reported as `0`: a field the source did not carry stays `null`, and for an upstream on the OpenAI protocol `cache_creation_input_tokens` is always `null` (cache creation is folded into `input_tokens`). `input_tokens` excludes cached tokens. Usage that is absent or all zero counts as not reported, and `reported` is then `false`.
- `complete` is `true` only when the reply finished normally. A stream counts as finished once its terminal marker was seen, `message_stop` on the Anthropic front and the `[DONE]` sentinel on the OpenAI front, so an upstream that closes without it is reported as truncated.
- `reason` is `"done"`, `"aborted"` (the signal fired, or the consumer stopped iterating), `"error"` (stream, connection or conversion failure) or `"upstream_error"` (a non-OK upstream status).
- `model`, `requested`, `upstream`, `front` and `stream` say which model was sent upstream, which one the client asked for, which endpoint answered, the client protocol and whether a stream was requested.

A partial stream reports the usage seen so far. On the OpenAI front the translator always asks the upstream for the final usage chunk of a stream so the report is complete whatever the client sent; the client receives that chunk only if it sent `stream_options.include_usage`. For an OpenAI client talking to an Anthropic upstream the numbers come from the upstream's own `usage` rather than from the converted output (`b7744c9`). With `streamUsage: false`, for upstreams that reject `stream_options`, the translator does not add the option to a pass-through request, so such streams report `reported: false` unless the client asked for usage itself (`98c66f7`).

### `route()` ([#76](https://github.com/CLDMV/llm-translator/issues/76), [#78](https://github.com/CLDMV/llm-translator/pull/78))

`api.route(body)` resolves a client request to its upstream without doing any I/O and returns `{ upstream, model, requested, protocol, backend, native, unserved }`: the endpoint name, the model name sent upstream after aliases and routing, the model the client asked for, the upstream protocol and backend, whether the body is forwarded without conversion, and whether no upstream lists the model. It uses the same routing as `request`, so a model allow-list can be checked before `send`. A body that is not an object throws a `TranslatorError` with status 400.

### Server `authorize` hook and `onUsage` ([#77](https://github.com/CLDMV/llm-translator/issues/77), [#78](https://github.com/CLDMV/llm-translator/pull/78))

`server.start` and `server.plugin` accept `authorize(request)`, sync or async. It runs on the API routes after the `apiKey` check (when one is set) and after the body is parsed; `/` and `/api/hello` skip it. `request` is `{ method, url, headers, body, front, route }`, where `route` is the `api.route(body)` result for any object body and `null` only for a body that is not an object or cannot be routed, so a hook that enforces a model allow-list should refuse a `POST` whose `route` is `null`. The hook answers `true` or `{ ok: true, context }` to let the request through, or `false` or `{ ok: false, status, message }` to refuse it (default `401` and `unauthorized`). Anything else, and a hook that throws or rejects, is a `401`, and the error goes to the request logger. A refusal is rendered in the front's own error format.

`onUsage(report, context)` on the server is called once per request with the usage report and the `context` the hook returned (`undefined` without a hook). It works without `authorize` too. A request whose client left before the route handler ran makes no upstream call and gets no `onUsage` call; once an upstream call has been made, `onUsage` is called exactly once, also when the client left.

## 🐛 Bug Fixes

These were found in review of the pull request and fixed before it merged.

- **An Anthropic client reply converted from an OpenAI-protocol upstream is metered from the upstream's own `usage`** (`95e0016`). The converted reply carries numbers the converter wrote for the client, so the converters now keep the upstream's counts on their state for `send` to read.
- **The OpenAI front over an Anthropic upstream is metered the same way** (`b7744c9`). Anthropic usage is reported the way the OpenAI front does, with cache creation folded into `input_tokens` and cached tokens named only when there are some, and a stream that fails partway still reports the counts seen so far instead of zeros.
- **Pass-through metering honors `streamUsage`, and an OpenAI-front stream is complete only at `[DONE]`** (`98c66f7`). With `streamUsage: false` the translator no longer adds `stream_options` to a pass-through request, and a chunk with a `finish_reason` no longer counts as the end of the stream.
- **`route()` and the hook's `route` were tightened** (`95e0016`). `backend` is now the driver detection chose (`vllm`, `openai`, `anthropic` or `compatible`) instead of the configured backend setting, and the `route` handed to `authorize` is set for every object body, with or without a `model`.
- **A stream that arrives after the client has left is closed** (`95e0016`), so its usage report is still delivered, and the server calls `onUsage` exactly once per upstream call.

## Upgrade notes

- No breaking changes. `send`, `request` and the server behave as in v0.2.0 unless you pass the new options.
- A non-loopback bind used to require an `apiKey`; it now accepts an `apiKey` or an `authorize` hook, and is still refused without either unless `allowUnauthenticated` is set.
- `authorize` and `onUsage` must be functions. Anything else passed to `server.start` or `server.plugin` throws a `TranslatorError` with the code `invalid_config`.
- The API is pre-1.0 and may change between minor versions.
