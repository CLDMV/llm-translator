# llm-translator v0.3.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 0.3.0 makes the translator usable as the metering and access-control layer of an app that serves several users, and widens the set of servers it can sit in front of. `send()` now reports the final token usage of every request, a new `route()` leaf says where a request would go before it is sent, and the server takes an `authorize(request)` hook and an `onUsage(report, context)` callback so an app with its own key system no longer has to rebuild the routes. The usage and hook work is [#76](https://github.com/CLDMV/llm-translator/issues/76) and [#77](https://github.com/CLDMV/llm-translator/issues/77), delivered in [#78](https://github.com/CLDMV/llm-translator/pull/78). The rest of the release adds drivers for llama.cpp, Ollama, SGLang and the DeepSeek API, endpoint pools with failover and load balancing, the `reasoningRoundTrip` and `toolSearch` settings, the `thinkOpen` and `toolFallback` settings, estimated usage in client replies when an upstream sends none, and `GET /v1/models/{id}`. It also raises the Node.js floor to 22.22.0 and removes the devcheck from the entry points. The second batch is tracked in [#22](https://github.com/CLDMV/llm-translator/issues/22), [#23](https://github.com/CLDMV/llm-translator/issues/23), [#24](https://github.com/CLDMV/llm-translator/issues/24), [#30](https://github.com/CLDMV/llm-translator/issues/30), [#33](https://github.com/CLDMV/llm-translator/issues/33), [#34](https://github.com/CLDMV/llm-translator/issues/34), [#36](https://github.com/CLDMV/llm-translator/issues/36), [#40](https://github.com/CLDMV/llm-translator/issues/40), [#45](https://github.com/CLDMV/llm-translator/issues/45), [#50](https://github.com/CLDMV/llm-translator/issues/50), [#56](https://github.com/CLDMV/llm-translator/issues/56).

## ✨ Features

### Final usage from `send()` ([#76](https://github.com/CLDMV/llm-translator/issues/76), [#78](https://github.com/CLDMV/llm-translator/pull/78))

Every reply from `send`, error replies included, has a non-enumerable `usage` property: a promise of one normalized report that never rejects. `send(body, { onUsage })` receives the same report exactly once, also when `send` throws because the caller aborted. For JSON and error replies the report is ready when `send` returns. For a stream it is delivered when the stream ends, fails or is stopped early (`break` or `return()`), and a stream nobody iterates never settles. The stream itself is passed through unchanged, so `api.sse.write` works as before, and an exception in `onUsage` is reported as a warning and never breaks the reply.

The report is `{ input_tokens, output_tokens, cache_read_input_tokens, cache_creation_input_tokens, reported, complete, reason, model, requested, upstream, front, stream }`:

- The four token fields are numbers or `null`. Unknown is never reported as `0`: a field the source did not carry stays `null`, and for an upstream on the OpenAI protocol `cache_creation_input_tokens` is always `null` (cache creation is folded into `input_tokens`). `input_tokens` excludes cached tokens. Usage that is absent or all zero counts as not reported, and `reported` is then `false`.
- `complete` is `true` only when the reply finished normally. A stream counts as finished once its terminal marker was seen, `message_stop` on the Anthropic front and the `[DONE]` sentinel on the OpenAI front, so an upstream that closes without it is reported as truncated.
- `reason` is `"done"`, `"aborted"` (the signal fired, or the consumer stopped iterating), `"error"` (stream, connection or conversion failure) or `"upstream_error"` (a non-OK upstream status).
- `model`, `requested`, `upstream`, `front` and `stream` say which model was sent upstream, which one the client asked for, which endpoint answered, the client protocol and whether a stream was requested.

A partial stream reports the usage seen so far. On the OpenAI front the translator always asks the upstream for the final usage chunk of a stream so the report is complete whatever the client sent; the client receives that chunk only if it sent `stream_options.include_usage`. For an OpenAI client talking to an Anthropic upstream the numbers come from the upstream's own `usage` rather than from the converted output (`b7744c9`). With `streamUsage: false`, for upstreams that reject `stream_options`, the translator does not add the option to a pass-through request, so such streams report `reported: false` unless the client asked for usage itself (`98c66f7`).

### `route()` ([#76](https://github.com/CLDMV/llm-translator/issues/76), [#78](https://github.com/CLDMV/llm-translator/pull/78))

`api.route(body)` resolves a client request to its upstream without doing any I/O and returns `{ upstream, model, requested, protocol, backend, native, unserved }`: the endpoint name, the model name sent upstream after aliases and routing, the model the client asked for, the upstream protocol and backend, whether the body is forwarded without conversion, and whether no upstream lists the model. It uses the same routing as `request`, so a model allow-list can be checked before `send`. A body that is not an object throws a `TranslatorError` with status 400.

### Server `authorize` hook and `onUsage` ([#77](https://github.com/CLDMV/llm-translator/issues/77), [#78](https://github.com/CLDMV/llm-translator/pull/78))

`server.start` and `server.plugin` accept `authorize(request)`, sync or async. It runs on the API routes after the `apiKey` check (when one is set) and after the body is parsed; `/` and `/api/hello` skip it. `request` is `{ method, url, headers, body, front, route }`, where `route` is the `api.route(body)` result for any object body and `null` only for a body that is not an object or cannot be routed, so a hook that enforces a model allow-list should refuse a `POST` whose `route` is `null`. The hook answers `true` or `{ ok: true, context }` to let the request through, or `false` or `{ ok: false, status, message }` to refuse it (default `401` and `unauthorized`). Anything else, and a hook that throws or rejects, is a `401`, and the error goes to the request logger. A refusal is rendered in the front's own error format.

`onUsage(report, context)` on the server is called once per request with the usage report and the `context` the hook returned (`undefined` without a hook). It works without `authorize` too. A request whose client left before the route handler ran makes no upstream call and gets no `onUsage` call; once an upstream call has been made, `onUsage` is called exactly once, also when the client left.

### Think output that starts inside a thought ([#22](https://github.com/CLDMV/llm-translator/issues/22))

The `thinkOpen` setting (default `false`) works with `thinkTags`. Some chat templates open `<think>` in the generation prompt, so the model's output starts inside the thought and only the closing `</think>` appears in the reply. With `thinkOpen: true` everything before the first `</think>` is reasoning, in JSON replies and in streams. Without a `</think>` the content stays plain text.

### Estimated usage when the upstream sends none ([#23](https://github.com/CLDMV/llm-translator/issues/23))

A server that returns no usage used to leave the client with zero token counts. When a converted reply's upstream did not report a side of the usage, `send` now writes an estimate for that side into the client-protocol reply and leaves a reported side alone. The input estimate comes from the driver's tokenizer when it has one (vLLM `/tokenize`, Anthropic `count_tokens`), else one token per four characters of the upstream request; the output estimate is one token per four characters of generated text, reasoning and tool names and arguments, at least 1. A reported 0 is real and is not replaced. The Anthropic front carries the estimate in the final `message_delta`, the OpenAI front in the final usage chunk. The usage report is not affected: its token fields stay `null` and `reported` stays `false`, and the new `estimated` field holds `{ input_tokens, output_tokens }` (`null` for a side the upstream reported, and `null` altogether when nothing was estimated) so a metering caller can use or ignore the guesses. Replies passed through without conversion are not altered.

### Tool-parser hint and the `toolFallback` setting ([#24](https://github.com/CLDMV/llm-translator/issues/24))

A vLLM server started without `--enable-auto-tool-choice` and `--tool-call-parser` answers any request with tools with a 400 that points at command-line flags. A 400 that names either flag now gets a sentence appended to the client-facing message saying which flags are missing, and a refusal naming `--jinja` (llama.cpp) is treated the same way. The new `toolFallback` setting (default `false`) makes `send` retry once without `tools`, `tool_choice` and `parallel_tool_calls`. The retry is not remembered, only one retry (images or tools) is made per request, and the result of the retry is returned as is. It is off by default because the request then runs without tools, which changes what the model can do.

### `GET /v1/models/{id}` ([#30](https://github.com/CLDMV/llm-translator/issues/30))

Both fronts of the server now answer `GET /v1/models/{id}` for a single model, as `GET /v1/models` already listed them.

### New drivers: llama.cpp, Ollama, SGLang and the DeepSeek API ([#33](https://github.com/CLDMV/llm-translator/issues/33), [#34](https://github.com/CLDMV/llm-translator/issues/34), [#36](https://github.com/CLDMV/llm-translator/issues/36), [#40](https://github.com/CLDMV/llm-translator/issues/40))

Four drivers join `vllm`, `openai`, `anthropic` and `compatible`. Detection binds each upstream to one driver once, and drivers now declare the GET paths they probe (`info().probes`) so a path is fetched once per upstream and the probes run in parallel. A vLLM server sees no extra requests. Generic OpenAI-compatible servers on a non-hosted host now also receive `/props`, `/get_server_info` and `/api/version` probes at startup, bounded by `detectTimeout`; setting `backend` skips them.

- **`llamacpp`** is matched through `/props` or `owned_by: "llamacpp"`. It sends `parallel_tool_calls: true` with tools, generates `call_...` ids for tool calls that have none, removes the `<think>` duplicate that `--reasoning-format deepseek-legacy` leaves in `content`, and renames `repetition_penalty` to `repeat_penalty` in pass-through bodies too. `repeat_penalty` and `grammar` are allowed through the OpenAI front's `passthroughFilter` for llama.cpp upstreams.
- **`ollama`** is matched by `GET /api/version`. It drops `tool_choice`, `n` and `logit_bias`, which Ollama's `/v1` endpoint lacks, and records them in `state.dropped`. An image given by URL becomes a text note, because the translator never fetches a URL a client supplied. `tool_choice: "none"` removes the tools as well. Ollama truncates a prompt that exceeds `num_ctx` without an error, so the driver warns once per upstream when a request is estimated to exceed the new `contextWindow` setting (the driver defaults it to 4096, `0` disables the check).
- **`sglang`** is matched through `/get_server_info` or `owned_by: "sglang"`. It sets `separate_reasoning: true` when a reasoning parser is running, never overriding the client, and lets `regex`, `ebnf` and `separate_reasoning` through the pass-through filter for SGLang upstreams only.
- **`deepseek`** is matched by the `api.deepseek.com` host. In thinking mode it removes the fields DeepSeek rejects (a forced `tool_choice`, `logprobs`), records the drops, disables `json_schema` response formats and images, and explains the `reasoning_content` refusal in the error the client sees. It turns `reasoningRoundTrip` on.

vLLM detection steps aside when `/v1/models` names `sglang` or `llamacpp`. A driver may also provide a `flush` hook that releases text its chunk normalizer was still holding when a stream ends, so a held `<` or `<thi` that turns out to be the answer is not lost.

Pass-through fields are now listed per driver. The vLLM extension fields (`top_k`, `min_p`, `chat_template_kwargs`, `repetition_penalty`, `skip_special_tokens` and so on) are allowed through `passthroughFilter` for the `vllm` and `compatible` drivers; llama.cpp and SGLang list the ones they accept, and the hosted drivers and Ollama list none.

### Endpoint pools: failover, load balancing and health ([#50](https://github.com/CLDMV/llm-translator/issues/50))

Upstreams that serve the same model after aliases now form a pool, ordered per request by the new `pool` config. `strategy` is `failover` (configuration order, the default and the previous behavior), `round_robin` or `least_busy` (fewest in-flight requests), and `pool.models` sets a strategy per model. `send` moves a request to the next member only on a connection error or a 5xx received before anything went to the client, at most once per endpoint, never after an abort and never for a 4xx or a stream that already started. A failing endpoint is skipped for `base * 2^(failures-1)` ms, capped at `max` (`pool.backoff`, defaults 1000 and 60000), and any answer below 500 resets it; unhealthy members are still tried when no healthy one is left. For models with more than one endpoint, `pool.connectTimeout` (default 10000 ms) and `pool.headersTimeout` (default off) turn a dead or hung host into a connection error eligible for failover. Nothing caps a reply once its headers have arrived.

`route()` now also returns `pool`, the names of the endpoints serving the model in the order they would be tried, without advancing a round robin. The usage report names the endpoint that answered. The new `api.endpoint.status()` leaf returns the pool config and one record per endpoint (`healthy`, `failures`, `retryAt`, `inflight`, `requests`, `errors`, `lastError`, `lastFailure`, `lastSuccess`), and `api.status().upstreams[].health` carries the same record. The server has no route for it.

### Reasoning round trip with `reasoningRoundTrip` ([#45](https://github.com/CLDMV/llm-translator/issues/45))

Some servers need the model's reasoning back with the conversation: DeepSeek refuses tool turns whose `reasoning_content` is missing, and OpenRouter's `reasoning_details` are structured and opaque. The `reasoningRoundTrip` setting (default `false`, on for the DeepSeek driver) carries that data across turns:

- **OpenAI-protocol upstream, Anthropic client.** The thinking block's signature becomes `llmt:` plus base64url of the provider's fields (`reasoning_content`, `reasoning` and/or `reasoning_details`) and the producer (`driver:protocol:host`). Payloads over 512 characters are deflated. On the next request a marked signature is decoded strictly and its fields are set on the assistant message exactly; data is restored only when the producer is the upstream the request goes to, otherwise the thinking text is used. Decoding is bounded (field types, sizes, nesting, and an inflate budget per request). The signature is not authenticated.
- **Anthropic upstream, OpenAI client.** The reply carries `reasoning_details` items (`reasoning.text` with a signature, and `reasoning.encrypted` for redacted thinking, format `anthropic-claude-v1`) that the client can replay, and replayed items become thinking and redacted thinking blocks again, in the OpenRouter convention for Claude.
- With neither a usable signature nor thinking text, the turn is sent without reasoning, and a tool turn in that state is counted and warned about once per upstream.

The signature carries the reasoning a second time, so the client stores roughly twice the thought (less after deflate), which is why it is off by default.

### Claude Code's tool search with `toolSearch` ([#56](https://github.com/CLDMV/llm-translator/issues/56))

Claude Code defers tools (`defer_loading`) and loads them through a client `ToolSearch` tool whose results carry `tool_reference` blocks, with a placeholder that must never be called. The new `toolSearch` setting controls how that reaches the model: `expand` (the default) rebuilds the tools list per request, with the non-deferred tools first, then the deferred tools the conversation has loaded in first-loaded order, then tools defined only in `ToolSearch` result text; the placeholder is never offered. `inline` offers every deferred tool up front and hides `ToolSearch`; `native` passes `defer_loading` and `tool_reference` through to a server that understands them (no built-in driver opts in yet). `deferredTools: "drop"` still removes deferred tools, and now `ToolSearch` too. With `expand`, chat templates that render tools into the system block cost one full prefill each time a tool is loaded, so `inline` or `ENABLE_TOOL_SEARCH=false` is the better choice where prefill is slow and the definitions are in the request.

## 🐛 Bug Fixes

These were found in review of [#78](https://github.com/CLDMV/llm-translator/pull/78) and fixed before it merged.

- **An Anthropic client reply converted from an OpenAI-protocol upstream is metered from the upstream's own `usage`** (`95e0016`). The converted reply carries numbers the converter wrote for the client, so the converters now keep the upstream's counts on their state for `send` to read.
- **The OpenAI front over an Anthropic upstream is metered the same way** (`b7744c9`). Anthropic usage is reported the way the OpenAI front does, with cache creation folded into `input_tokens` and cached tokens named only when there are some, and a stream that fails partway still reports the counts seen so far instead of zeros.
- **Pass-through metering honors `streamUsage`, and an OpenAI-front stream is complete only at `[DONE]`** (`98c66f7`). With `streamUsage: false` the translator no longer adds `stream_options` to a pass-through request, and a chunk with a `finish_reason` no longer counts as the end of the stream.
- **`route()` and the hook's `route` were tightened** (`95e0016`). `backend` is now the driver detection chose (`vllm`, `openai`, `anthropic` or `compatible`) instead of the configured backend setting, and the `route` handed to `authorize` is set for every object body, with or without a `model`.
- **A stream that arrives after the client has left is closed** (`95e0016`), so its usage report is still delivered, and the server calls `onUsage` exactly once per upstream call.

Fixes to behavior that shipped in v0.2.0:

- **`token.count` against an Anthropic upstream now forwards `mcp_servers` and `context_management`**, which `count_tokens` accepts but the request was leaving out (`b22e4fb`).
- **`pdf.scale` is validated.** A value that is not a positive number now throws a `TranslatorError` with the code `invalid_setting` naming the setting, instead of reaching the PDF renderer, which throws on a scale of 0 since unpdf 2 (`5056e5f`).

- `unpdf` 2 declares Node.js 24 or later in its own `engines`, so npm prints an `EBADENGINE` warning when installing on Node.js 22. The translator's tests pass on 22.22.0, 24 and 26.

## Upgrade notes

- **Node.js 22.22.0 or newer is required** (was 22.15.0). See Requirements.
- **`pdf.scale` must be a positive number.** A value of `0`, a negative number, `NaN` or a non-number now throws a `TranslatorError` with the code `invalid_setting` instead of being passed on to the PDF renderer.
- **Tool search changed default.** `toolSearch` defaults to `expand`: a deferred tool is offered once the conversation has loaded it, and the `DeferredToolPlaceholder` is never offered. v0.2.0 offered every deferred tool as an ordinary tool. Set `toolSearch: "inline"` for the old up-front behavior.
- **Estimated usage in client replies.** When an upstream omits usage, the client now sees estimated token counts instead of zeros. The usage report is unchanged: `reported` stays `false` and the token fields stay `null`.
- **Pass-through fields are per driver.** With `passthroughFilter` on (the server default), the vLLM extension fields are forwarded only to upstreams on the `vllm` and `compatible` drivers; an upstream detected as `openai` or `anthropic` no longer receives them.
- **More drivers can claim an upstream.** A llama.cpp, Ollama, SGLang or `api.deepseek.com` upstream that v0.2.0 treated as vLLM or generic now gets its own driver, with its settings and request fixes. A generic upstream is probed on three more paths at startup; set `backend` on the upstream to skip detection. `route().backend` and `status()` can now report `llamacpp`, `ollama`, `sglang` or `deepseek`. The DeepSeek driver turns `reasoningRoundTrip` on, so its thinking signatures start with `llmt:`.
- The devcheck is gone. Without the `llm-translator-dev` condition a checkout resolves to `dist/`, so run `npm run build` first or pass `--conditions=llm-translator-dev` to use `src/`. Published packages are unaffected.
- No other breaking changes. `send`, `request` and the server behave as in v0.2.0 unless you pass the new options.
- A non-loopback bind used to require an `apiKey`; it now accepts an `apiKey` or an `authorize` hook, and is still refused without either unless `allowUnauthenticated` is set.
- `authorize` and `onUsage` must be functions. Anything else passed to `server.start` or `server.plugin` throws a `TranslatorError` with the code `invalid_config`.
- The API is pre-1.0 and may change between minor versions.
