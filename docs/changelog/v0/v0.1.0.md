## Overview

First release. It sets up the package itself: the source layout, the build, the tests and the CLDMV v4 CI/release pipeline. The translation API is not implemented yet; the only export is `name`, a placeholder that keeps the build and tests real until the first feature lands.

The package follows the [CLDMV library package layout](https://github.com/CLDMV/.github/blob/master/docs/conventions/package-layout.md) and is its reference implementation.

## ✨ Features

### ESM and CommonJS entry points ([#1](https://github.com/CLDMV/llm-translator/pull/1))

`import` and `require` both work. `src/index.mjs` is bundled by tsup into `dist/index.mjs`. `src/index.cjs` is a few lines that load that bundle through Node's synchronous `require(esm)`, copied verbatim into `dist/index.cjs` rather than bundled a second time. On a Node.js version without `require(esm)` it throws a clear `ERR_REQUIRE_ESM` that says to use `import()` instead. That is why `engines.node` is `>=20.19.0`.

### `llm-translator-dev` condition and devcheck ([#1](https://github.com/CLDMV/llm-translator/pull/1))

In a source checkout, `--conditions=llm-translator-dev` (on the node CLI or in `NODE_OPTIONS`) routes both `import` and `require` of `@cldmv/llm-translator` to `src/` instead of `dist/`. A root `devcheck.mjs`, which is never published, exits with setup instructions when a checkout runs without that condition. It skips in CI and when the package is installed under `node_modules`, and it is imported asynchronously so it never blocks `require()`.
