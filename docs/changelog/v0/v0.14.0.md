# llm-translator v0.14.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 0.14.0 adds two cloud upstreams and one opt-in fetch. Claude can be reached on Google Vertex AI and on Amazon Bedrock, and Bedrock's other models are reached over its Converse API. `document` blocks with a `url` source can now be downloaded and converted, behind an allow-list.

Nothing changes for an existing setup. Both drivers bind only to their own hosts or to an explicit `backend`, and URL fetching is off until `documentUrls` is set. No new dependencies: Google auth, SigV4 signing and the AWS event stream are implemented on `node:crypto` and the translator's own transport. Neither cloud driver has been run against the real service yet; that is tracked in [#70](https://github.com/CLDMV/llm-translator/issues/70).

## ✨ Features

### Google Vertex AI upstream for Claude ([#179](https://github.com/CLDMV/llm-translator/pull/179))

The new `vertex` driver sends Claude requests to Vertex AI's `rawPredict` and `streamRawPredict` endpoints, with the model in the path and `anthropic_version: "vertex-2023-10-16"` in the body. Regional hosts, `global` and the `us` and `eu` multi-regions are handled, and token counts use Vertex AI's `count-tokens` endpoint with the usual estimate as a fallback. Settings go in one `vertex` object on the upstream (`project`, `region`, `credentials`, `accessToken`, `getToken`, `metadataServer`), with `ANTHROPIC_VERTEX_PROJECT_ID`, `GOOGLE_CLOUD_PROJECT` and `CLOUD_ML_REGION` read from the environment. `url` may be left out: it follows from the region.

Access tokens come from, in order, `getToken`, `accessToken`, the upstream's `apiKey`, a service account or `authorized_user` key in `credentials`, `GOOGLE_ACCESS_TOKEN`, a key file named by `GOOGLE_APPLICATION_CREDENTIALS`, gcloud's application default credentials file, and the GCE metadata server when `metadataServer` is set. Tokens are cached until a minute before they expire. See [docs/drivers.md](https://github.com/CLDMV/llm-translator/blob/master/docs/drivers.md#google-vertex-ai-claude). Resolves [#47](https://github.com/CLDMV/llm-translator/issues/47).

### Amazon Bedrock upstream ([#182](https://github.com/CLDMV/llm-translator/pull/182))

The new `bedrock` driver talks to the Bedrock runtime. Under `api: "auto"` a Claude model id (bare, with a geography prefix such as `us.` or `global.`, or an ARN) goes through InvokeModel with the Anthropic body and `anthropic_version: "bedrock-2023-05-31"`. Every other model goes through Converse, a new protocol `bedrock.converse` (alias `converse`) with converters for both client protocols. Streams are decoded from AWS's binary event stream, with both CRCs checked.

Requests are signed with SigV4, which is checked against AWS's published test vectors, or sent with a Bedrock API key. Credentials come from the upstream's `apiKey`, `accessKeyId`, `secretAccessKey` and `sessionToken`, then `AWS_BEARER_TOKEN_BEDROCK` and the usual `AWS_*` variables; the region from `region`, the host name, `AWS_REGION` or `AWS_DEFAULT_REGION`. `GET /models` is answered from Bedrock's `foundation-models` list. Gaps that remain (prompt caching points, Converse reasoning signatures, `response_format` over Converse, the AWS SDK credential chain, `anthropic_beta`, CountTokens) are listed in [#180](https://github.com/CLDMV/llm-translator/issues/180). See [docs/drivers.md](https://github.com/CLDMV/llm-translator/blob/master/docs/drivers.md#amazon-bedrock) and [docs/protocol-support.md](https://github.com/CLDMV/llm-translator/blob/master/docs/protocol-support.md#11-amazon-bedrock-converse). Resolves [#46](https://github.com/CLDMV/llm-translator/issues/46).

### Fetch URL document sources ([#181](https://github.com/CLDMV/llm-translator/pull/181))

The new `documentUrls` setting downloads the `url` source of a `document` block and converts it like a `base64` one, so a PDF becomes page text plus page images. It is `null` (off) by default; `{ allow: ["docs.example.com", "*.example.org"] }` turns it on.

- Only hosts on `allow` are fetched, and every address a name resolves to must be public unless `allowPrivate` is set. The connection is pinned to the address that was checked.
- Each redirect is checked again, and `https` to `http` is refused. Limits: `maxBytes` (32 MiB), `timeout` (30 s), `maxRedirects` (3), `maxDocuments` (10 per request).
- Only PDF and plain text are accepted. A failed fetch falls back to the existing text note and a `document/fetch` warn event.

See [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#documenturls) and the [SSRF notes](https://github.com/CLDMV/llm-translator/blob/master/docs/protocol-support.md#ssrf-protections). Resolves [#18](https://github.com/CLDMV/llm-translator/issues/18).

## 🔧 Drivers

Two driver hooks were added for these backends, and third-party drivers can use them too: an `auth` leaf returns the headers for a request whose credentials have to be fetched, and a `sign` leaf signs the finished URL, headers and body. The `path` leaf now also gets `protocol` and `stream`. See [docs/drivers.md](https://github.com/CLDMV/llm-translator/blob/master/docs/drivers.md#architecture).

## Upgrade notes

- No breaking changes. Existing upstreams bind and behave as before.
- To use Vertex AI, add an upstream with `backend: "vertex"`, a `vertex` object and the model ids in `models` (Vertex AI has no model list). To use Bedrock, add one with `backend: "bedrock"` and a region, or point `url` at a `bedrock-runtime` host.
- To fetch URL documents, set `documentUrls: { allow: [...] }`. A request that carries URL documents and no setting still gets the text note, as before.
