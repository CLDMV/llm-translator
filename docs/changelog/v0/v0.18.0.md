# llm-translator v0.18.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 0.18.0 adds both batch APIs, OpenAI's `/v1/batches` and Anthropic's `/v1/messages/batches`, run in-process through the normal request path so every upstream works, and the stateful side of the Responses API: stored responses, `previous_response_id`, the Conversations API, background mode, `item_reference` inputs and stored prompts, all on a translator-side store.

Existing setups keep working. Both features are on by default with in-memory stores and can be turned off with `batches: null` and `responses: null`. Nothing adds a dependency. Neither has been run against real clients and providers yet; real-backend checks are tracked in [#62](https://github.com/CLDMV/llm-translator/issues/62).

## ✨ Features

### Batch API and Message Batches ([#204](https://github.com/CLDMV/llm-translator/pull/204))

The OpenAI front serves `/v1/batches` and the Anthropic front serves `/v1/messages/batches`, both on one in-process runner. Each request in a batch goes through the same path as a normal request, so every upstream and every conversion works.

- **OpenAI Batch API.** The input is a `purpose: "batch"` file from the Files API, one request per line, for `/v1/chat/completions`, `/v1/responses` or `/v1/embeddings`. The input is checked as a whole before anything runs. Results are written to `output_file_id` and `error_file_id` files when the batch ends. Create, list, get and cancel are served.
- **Anthropic Message Batches.** Create, list, get, cancel, delete and the JSONL results stream, with `succeeded`, `errored`, `canceled` and `expired` results in request order.
- **The `batches` setting** picks a memory or disk store and sets the concurrency across all batches (4 by default), the request and batch limits, the completion window (24 hours) and the retention (29 days). A batch still running when the process stopped ends `expired` at the next start.

Batches run in the translator process, not on a provider's batch infrastructure, so there is no price discount. See [docs/server.md](https://github.com/CLDMV/llm-translator/blob/master/docs/server.md#message-batches) and [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#batches). Resolves [#29](https://github.com/CLDMV/llm-translator/issues/29), resolves [#25](https://github.com/CLDMV/llm-translator/issues/25).

### Stateful Responses API ([#205](https://github.com/CLDMV/llm-translator/pull/205))

The Responses front used to be stateless and refused `previous_response_id`, `conversation`, `store: true`, `background: true`, stored prompts and `item_reference` inputs. It now serves all of them from a response store.

- **Stored responses.** Responses are kept by default (`store` defaults to true, as on OpenAI). `GET`, `DELETE` and `GET /v1/responses/{id}/input_items` are served, and `previous_response_id` replays the stored history to any upstream.
- **Conversations API.** `/v1/conversations` and its items routes, and `conversation` on a response request, which reads the conversation's items and appends the new ones when the response ends.
- **Background mode.** `background: true` returns at once and keeps running without the client; poll it with `GET`, stream it again, or stop it with `POST /v1/responses/{id}/cancel`.
- **`item_reference` inputs** are looked up in the stored responses and conversations.
- **Stored prompts** come from the new `responses.prompts` setting, with versions and `{{variable}}` substitution, including image and file parts as variables.
- **The `responses` setting** picks a memory or disk store, or your own backend with four functions (`scan`, `read`, `write`, `erase`) so records can live in a database or cache. It also sets limits on count, total bytes, lifetime, conversations and items per conversation.

The same operations are exported as leaves (`api.responses.get`, `api.conversations.create` and so on) for your own server. See [docs/server.md](https://github.com/CLDMV/llm-translator/blob/master/docs/server.md#stored-responses-and-conversations), [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#responses) and [docs/protocol-support.md](https://github.com/CLDMV/llm-translator/blob/master/docs/protocol-support.md#84-stored-responses-conversations-and-background). Resolves [#8](https://github.com/CLDMV/llm-translator/issues/8).

## Upgrade notes

- No breaking changes.
- Responses made through the Responses front are now kept in memory by default, up to 1000 responses or 128 MiB. Send `store: false` per request, set `responses: null` to turn the stateful features off, or use `responses: { store: "disk", dir: "..." }` to keep them across restarts.
- Both batch APIs are on by default with an in-memory store. Set `batches: null` to turn them off, or `batches: { store: "disk", dir: "..." }` to keep finished batches across restarts.
- The stores are per process. Two translator instances don't see each other's responses or batches.
