# llm-translator v0.2.0 Changelog

**Release Date**: October 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 0.2.0 is the first release with a working translator. It converts requests, responses and streams between the Anthropic Messages API and the OpenAI Chat Completions API in both directions, detects the server behind an upstream (vLLM first, then any OpenAI-compatible server), and ships an optional standalone server and CLI so Claude Code can run against a local model. The placeholder export from [v0.1.0](./v0.1.0.md) is gone; the package now exports `createTranslator`.

This is a 0.x release and should be read as one. It has been validated end to end for one path: Claude Code 2.1.310 in print mode, through the translator, to vLLM 0.32.0 serving Qwen3-1.7B on a CPU. The converters are covered by a suite at 100% line, branch, function and statement coverage against fake upstreams. Everything that needs another backend, client, model family or an API key has not been run and is tracked in the epic [Real-backend validation (#62)](https://github.com/CLDMV/llm-translator/issues/62); the list is also in the "Untested paths" section of [docs/testing.md](https://github.com/CLDMV/llm-translator/blob/master/docs/testing.md). What is and is not translated is spelled out in the [feature inventory](https://github.com/CLDMV/llm-translator/blob/master/docs/feature-inventory.md) (80 of 176 catalogued features implemented, 11 partial) and in [known limitations](https://github.com/CLDMV/llm-translator/blob/master/docs/known-limitations.md). Expect the API to move.

The whole release landed as one pull request, [#72](https://github.com/CLDMV/llm-translator/pull/72). `engines.node` is now `>=22.15.0`.

## ✨ Features

### Anthropic Messages ⇄ OpenAI Chat Completions converters ([#72](https://github.com/CLDMV/llm-translator/pull/72))

Six converters, one pair per direction for request, response and stream. Text, images, documents, tool use and tool results, tool-choice, system prompts (including the mid-conversation system messages Claude Code sends), usage, stop reasons and errors are mapped, and anything without a counterpart is dropped and recorded in `state.dropped`, rejected with an error, or replaced by a text note rather than guessed at. Anthropic `thinking` becomes the server's reasoning request and the server's reasoning comes back as thinking blocks, including a leading `<think>` block parsed out of content. Anthropic `document` blocks with a PDF are expanded into per-page text plus, when the model accepts images and `@napi-rs/canvas` loads, page images. The mapping tables are in [docs/protocol-support.md](https://github.com/CLDMV/llm-translator/blob/master/docs/protocol-support.md) and the tunables in [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md).

### Backend detection and drivers ([#72](https://github.com/CLDMV/llm-translator/pull/72))

`createTranslator` probes each upstream and binds it to a driver: `vllm`, `openai`, `anthropic` or the generic `compatible` driver. The vLLM driver maps the detected version to settings (for example the reasoning field name and `thinking_token_budget`), asks the chat template whether it accepts mid-conversation system messages, and checks whether the served model accepts images (`7f1fed5`). Models route by alias, by the endpoint that serves them, or to a default endpoint; when both sides speak the same protocol the body is forwarded without conversion. Details in [docs/drivers.md](https://github.com/CLDMV/llm-translator/blob/master/docs/drivers.md).

### Standalone server, Fastify plugin and CLI ([#72](https://github.com/CLDMV/llm-translator/pull/72))

`api.server.start()`, a Fastify plugin and the `llm-translator` command serve either front: `anthropic` (`POST /v1/messages`, `count_tokens`, `GET /v1/models`) or `openai` (`POST /v1/chat/completions`). Fastify is an optional peer dependency. A non-loopback bind requires an API key, client headers are forwarded to a native Anthropic upstream through an allow-list, and errors are always rendered in the front's own shape. The CLI reads flags, environment variables and a JSON config file, and prints one line per upstream at startup with the detected driver, version and probe results (`33c9c98`, `1ea9acd`). See [docs/server.md](https://github.com/CLDMV/llm-translator/blob/master/docs/server.md) and the Claude Code walkthrough in [docs/claude-code.md](https://github.com/CLDMV/llm-translator/blob/master/docs/claude-code.md).

### Tool calls are buffered by default (`06517d8`)

OpenAI-style servers stream a tool call as argument fragments. The default `toolStreaming: "buffer"` holds each call until its arguments are complete and emits one whole `tool_use` block, which is what Claude Code handles reliably; `"stream"` forwards the fragments as they arrive. Error types for 5xx replies were aligned with each protocol at the same time.

### Retry once without images when a model refuses them (`9e88024`)

When an OpenAI-protocol upstream answers a request that carried images with a 400 that says the model does not accept images, the translator retries once with the images replaced by a short text note (PDF pages keep their text) and remembers the endpoint and model as text-only for the rest of the process. Streaming and non-streaming requests behave the same, in `send` and in the server. The `imageFallback` setting (default on) turns it off; other 400s are never retried. The vLLM wording was seen from a real server; the other wordings it recognises were written from knowledge and are tracked in [#70](https://github.com/CLDMV/llm-translator/issues/70).

## 🐛 Bug Fixes

These were found by running real Claude Code sessions against a real vLLM and are the reason the release is described as validated for that path.

### Slow upstreams are no longer cut off after 300 seconds (`1811862`)

Node's `fetch` aborts when no response headers arrive for five minutes, and vLLM only sends headers with the first token, so a long prefill on a slow machine always failed. The default transport is now a small `node:http` implementation with no timeouts, no redirect following and no compression.

### Claude Code's stream watchdog is kept satisfied (`cb6862f`, `68a9e39`)

Claude Code aborts a stream and resends the request after 300 seconds without a real stream event, and it does not count `ping` events. When the upstream has not answered within the ping interval the server now commits to the stream early with `message_start` and an empty thinking block and sends empty deltas on the open block as keep-alives. When the upstream's first block is thinking it takes over the early block; otherwise the early block is closed and the following indices shift by one. Unexpected failures after the reply is committed no longer leak their message to the client.

### Answers no longer start with blank lines (`392a218`)

The blank lines models put between their reasoning and the answer are dropped, in streams and in complete replies.

### Text-only models and stale sockets (`7f1fed5`)

A text-only model answered `400 ... is not a multimodal model` to the page images of a PDF, which broke every request that read a PDF. The vLLM driver now sends a one-token request with a 1x1 image at startup (unless `images` is configured) and turns images off when the model is not multimodal. The default transport also opens a fresh connection per request, which removed stale keep-alive socket resets.

### CodeQL findings and server teardown (`115532b`, `814fd7d`)

Upstream URL normalization uses a linear loop instead of a backtracking regular expression, and the ping cleanup no longer carries an always-false check. The server tears down cleanly when a client disconnects.

## 🔧 CI & tooling

- **100% coverage is enforced on every CI run** (`a442d42`). The matrix runs `npm run ci:coverage`, so a drop in lines, statements, functions or branches fails the required check, not only the badge job. The CI Node floor is 22.15 (`814fd7d`).
- **Real-backend harness in `tools/e2e/`** (`9042ffd`, `19aec40`): a script that starts vLLM on a CPU in Docker, a scripted fake vLLM, a logging proxy and a runner that drives Claude Code with an isolated home. Not published to npm; covered by [docs/testing.md](https://github.com/CLDMV/llm-translator/blob/master/docs/testing.md).
