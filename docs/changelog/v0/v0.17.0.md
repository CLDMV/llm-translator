# llm-translator v0.17.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `next` → `master`

---

## Overview

Version 0.17.0 adds a Files API on both fronts, sends Anthropic's client tools (bash, text editor, computer and memory) to other upstreams as function tools, and closes the gaps left in the Amazon Bedrock driver: the AWS credential chain, Converse prompt caching, reasoning round trips, structured output, `anthropic-beta` passthrough and real token counts.

Existing setups work as before. Nothing adds a dependency: the AWS credential chain and the multipart upload parser are written in-repo. None of the new upstream paths has been run against the real services yet; that is tracked in [#70](https://github.com/CLDMV/llm-translator/issues/70).

---

## ✨ Features

### Files API ([#202](https://github.com/CLDMV/llm-translator/pull/202))

Both fronts now serve `/v1/files` (upload, list, get, content, delete) from one store, so a file uploaded through either front can be referenced from either. The store keeps files in memory or on disk, with limits on file size, file count, total bytes and lifetime, set by the new global `files` setting (`null` turns the Files API off).

- Stored files are read into base64 before conversion when a request references them: Anthropic `file` image and document sources, OpenAI `file_id` parts, and Responses `input_file` and `input_image`.
- An unknown id is forwarded untouched on as-is routes, and gets the front's own 404 everywhere else.
- A Responses `input_file` by `file_url` goes through the existing URL document fetch when `documentUrls` is on.

See [docs/server.md](https://github.com/CLDMV/llm-translator/blob/master/docs/server.md#files-api), [docs/settings.md](https://github.com/CLDMV/llm-translator/blob/master/docs/settings.md#files) and [docs/protocol-support.md](https://github.com/CLDMV/llm-translator/blob/master/docs/protocol-support.md#24-files-a-to-o-and-o-to-a). Resolves [#17](https://github.com/CLDMV/llm-translator/issues/17).

### Anthropic client tools on other upstreams ([#199](https://github.com/CLDMV/llm-translator/pull/199))

`bash`, `text_editor`, `computer` (including the `computer_toolset` form) and `memory` used to be dropped on the way to a non-Anthropic upstream. They now go as ordinary function tools built from the input fields Anthropic publishes, and the calls come back under the client's own tool name. For memory and computer, the system prompt text Anthropic publishes for those tools is added to the system prompt. Anthropic's models have these tools built in; another model only sees the written description, so it may use them less reliably.

See [docs/protocol-support.md](https://github.com/CLDMV/llm-translator/blob/master/docs/protocol-support.md#11-anthropic-request-to-chat-completions-request-a-to-o). Resolves [#19](https://github.com/CLDMV/llm-translator/issues/19).

### Amazon Bedrock gaps closed ([#200](https://github.com/CLDMV/llm-translator/pull/200))

- **The AWS credential chain**, read without the AWS SDK: the upstream's new `profile` setting (or `AWS_PROFILE`), the shared config and credentials files, `credential_process`, SSO logins with token refresh, assume-role and web identity profiles, the environment's web identity, the ECS task role and the EC2 instance role. A profile with `mfa_serial` is refused.
- **Prompt caching over Converse.** Anthropic `cache_control` markers become `cachePoint` blocks right after the marked tool, system block or content block, at most four. `settings.bedrock.cache: false` turns this off for a model that rejects `cachePoint`.
- **Reasoning round trips over Converse.** Reasoning signatures and redacted reasoning come back in the thinking block's signature and are sent back on the next turn, so Claude keeps its thinking across tool calls.
- **Structured output over Converse.** `response_format` (and `output_config.format`) is sent as a forced `json_response` tool and its input comes back as the reply text.
- **`anthropic-beta` over InvokeModel.** A client's `anthropic-beta` header names are added to the body's `anthropic_beta` list.
- **Token counts** use Bedrock's `CountTokens` and fall back to the estimate when the model or the permissions don't allow it.
- **Raw capture** of a Bedrock stream now records the decoded events instead of the binary frames read as text.

See [docs/drivers.md](https://github.com/CLDMV/llm-translator/blob/master/docs/drivers.md#amazon-bedrock) and [docs/protocol-support.md](https://github.com/CLDMV/llm-translator/blob/master/docs/protocol-support.md#11-amazon-bedrock-converse). Resolves [#180](https://github.com/CLDMV/llm-translator/issues/180).

## Upgrade notes

- No breaking changes.
- The Files API is on by default with an in-memory store. Set `files: null` to turn it off, or `files: { store: "disk", dir: "..." }` to keep files across restarts.
- Anthropic client tools now reach non-Anthropic upstreams instead of being dropped. A request that only carried such tools used to reach the model with no tools.
