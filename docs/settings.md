# Settings

Settings tune how the converters map one protocol onto the other. They are resolved in layers with later layers winning: library defaults, then detected or probed values, then driver defaults, then global `settings`, then per-endpoint `settings`. Undefined values never override an earlier layer. The `pdf` and `sampling` objects merge key by key; every other key is replaced whole. Enumerated keys are validated and an invalid value throws a `TranslatorError` with the code `invalid_setting`.

Every converter accepts an optional `settings` argument (partial objects are fine) and resolves it with `resolve()` from `src/lib/settings.mjs`, so direct callers get the same defaults as the server.

## Pool config (not a converter setting)

Failover and load balancing between upstreams that serve the same model are configured with the translator's `pool` key, not with `settings`: `strategy` (`failover`, `round_robin`, `least_busy`), `models` (strategy per model after aliases) and `backoff` (`base` and `max` in ms), `connectTimeout` and `headersTimeout` (ms). It is described in [server.md](server.md#endpoint-pools-failover-and-load-balancing). An invalid value throws a `TranslatorError` with the code `INVALID_CONFIG` when the translator is created.

## Effort levels and pinned aliases (not converter settings)

Which reasoning effort levels a model honours is configured with the translator's `efforts` key, keyed by the model name after aliases. A value is a list of levels (`minimal`, `low`, `medium`, `high`, `xhigh`, `max`) or `{ "levels": [...], "default": ... }`:

```json
{
	"efforts": {
		"GLM-5.3-Flash": ["low", "high", "max"],
		"other-model": { "levels": ["low", "high"], "default": null }
	}
}
```

For a model with a list, on an OpenAI-protocol upstream:

- a requested level in the list is sent as is, `max` and `xhigh` included, whatever `effortPassthrough` says;
- any other level snaps to the nearest one in the list (a tie goes to the higher level) and one warning is printed per message;
- a request that does not turn reasoning off and names no effort gets `default`: a level from the list, `null` to send nothing because the model has its own default, or, when `default` is left out, the level nearest to `medium`. The translator no longer sends `medium` for such a model;
- `none` and a disabled thinking mode are never changed.

A model without a list behaves as before: `max` and `xhigh` become `high` unless `effortPassthrough` is on, and a thinking request in `reasoning_effort` mode with no effort sends `medium`.

An alias can pin settings instead of only renaming the model: `"aliases": { "glm-flash-max": { "model": "GLM-5.3-Flash", "effort": "max" } }`. `effort` replaces the request's effort (it is mapped even when the `effort` setting is off) and then goes through the model's list. `thinking: false` turns thinking off and `thinking: true` undoes a client's `disabled`. A plain string alias works as before. See [server.md](server.md#aliases-that-pin-settings) for the models endpoint.

## Where settings come from

The vLLM driver derives some values from the detected server version (for example `reasoningField` and `thinkingBudget`), the `compatible` driver uses conservative defaults, and each upstream in the configuration can pin its own `settings`. The server layer documents the configuration file; this page covers the converter keys only.

## Examples

A text-only model behind vLLM 0.15, with Claude Code's deferred tools turned off at the client:

```json
{
	"settings": {
		"images": false,
		"reasoningField": "reasoning_content",
		"inlineSystem": "user",
		"toolSchema": "sanitize"
	}
}
```

Rejecting anything the translator cannot map instead of dropping it:

```json
{ "settings": { "unknownFields": "error", "documents": "error" } }
```
