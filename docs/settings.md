# Settings

Settings tune how the converters map one protocol onto the other. They are resolved in layers with later layers winning: library defaults, then detected or probed values, then driver defaults, then global `settings`, then per-endpoint `settings`. Undefined values never override an earlier layer. The `pdf` and `sampling` objects merge key by key; every other key is replaced whole. Enumerated keys are validated and an invalid value throws a `TranslatorError` with the code `invalid_setting`.

Every converter accepts an optional `settings` argument (partial objects are fine) and resolves it with `resolve()` from `src/lib/settings.mjs`, so direct callers get the same defaults as the server.

| `toolStreaming`      | `"buffer"`                 | `"buffer"`, `"stream"`                                               | OpenAI-style server to Anthropic client streams. `buffer` holds every tool call until the stream finishes and then emits all of them in index order, each as one whole `tool_use` block (start, one `input_json_delta`, stop). Text and thinking stream immediately in arrival order, so they appear before the tool blocks, and fragments can never arrive too late. The cost is that tool arguments are not shown incrementally; total completion time is unchanged. `stream` forwards argument fragments incrementally and holds text that arrives while a tool block is open until the tool blocks are done.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| `effortPassthrough`  | `false`                    | boolean                                                              | vLLM driver: send `xhigh` and `max` reasoning effort unchanged. By default they are clamped to `high`, unless the model has an `efforts` list (below), because vLLM rejects values other than `low`, `medium` and `high` on most versions and models.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `passthroughFilter`  | `false`                    | boolean                                                              | OpenAI front with an OpenAI-protocol upstream: restrict the forwarded body to standard Chat Completions fields plus documented vLLM extensions, so a client cannot inject arbitrary server fields. Off in the library; `server.start` and `server.plugin` turn it on unless the global setting is `false`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `nativeMessages`     | `false`                    | `true`, `false`, `"auto"`                                            | Deprecated: use the upstream's `api` (see [Upstream `api`](#upstream-api-not-a-converter-setting)). For a vLLM upstream that sets no `api`, `true` reads as `api: "messages"`, `"auto"` as `api: "auto"` and `false` as `api: "chat"`, with a one-time warning; it is ignored, with a warning, when `api` is set.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `contextWindow`      | `0`                        | integer (tokens), 0 = unknown                                        | Prompt size in tokens at which the upstream silently truncates. When above 0, a driver that knows its server truncates (Ollama sets `4096`, its default `num_ctx`) prints one warning per upstream the first time a request is estimated to exceed it. Only the warning uses it: nothing is truncated or rejected by the translator.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `defaultMaxTokens`   | `8192`                     | integer                                                              | `max_tokens` used when an OpenAI request omits both `max_tokens` and `max_completion_tokens` (Anthropic requires one).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

## `documentUrls`

`documentUrls` makes the translator download the `url` source of a `document` block, then convert the bytes like a `base64` document (a PDF becomes page text plus page images, plain text stays text). It is `null` (off) by default, and an object turns it on. The fetch happens in the root api before conversion, so the converters stay free of I/O, and it is skipped for a request that is forwarded to an Anthropic upstream as it is, when `documents` is `note` or `error`, and when `documentConverter` is set (the converter still runs first and gets the block as it came).

| Field          | Default              | Meaning                                                                                                                                                                                            |
| -------------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `allow`        | required, no default | List of hosts that may be fetched: an exact host name or `*.example.com` (any subdomain, not the bare domain). Must not be empty. `"*"` allows any host, and the address checks still apply to it. |
| `maxBytes`     | `33554432`           | Size limit in bytes (Anthropic's PDF limit), checked against `Content-Length` and again as the body arrives. `pdf.maxBytes` still applies to a PDF afterwards.                                     |
| `timeout`      | `30000`              | Milliseconds for the whole fetch: name lookups, redirects and the body.                                                                                                                            |
| `maxRedirects` | `3`                  | Redirects followed. Each hop is checked against `allow` and the address rules again, and `https` to `http` is refused.                                                                             |
| `maxDocuments` | `10`                 | Different URLs fetched per request; the rest become notes. The same URL in one request is fetched once.                                                                                            |
| `allowPrivate` | `false`              | Allow loopback, private, link-local and the other non-public addresses. Off unless the allowed hosts are on your own network.                                                                      |

```js
settings: {
	documentUrls: {
		allow: ["files.example.com", "*.cdn.example.com"];
	}
}
```

An invalid value (an empty or missing `allow`, a key that is not listed, a limit that is not a positive integer) throws a `TranslatorError` with code `invalid_setting`. A document that cannot be fetched becomes a text note with the reason and a `document` event; it never fails the request. See [protocol-support.md](protocol-support.md#fetching-url-documents) for what is fetched and the SSRF protections.

## Upstream `api` (not a converter setting)

`api` is set on an upstream, next to `url` and `backend`, not in `settings`. It picks the protocol the translator speaks to that upstream: `"auto"` (the default), `"anthropic.messages"`, `"openai.chat"`, `"openai.responses"`, `"ollama.chat"`, `"bedrock.converse"`, `"google.gemini"` or `"cohere.chat"`, plus the aliases `"converse"`, `"gemini"`, `"google"` and `"cohere"` and the aliases `"messages"`, `"anthropic"`, `"claude"`, `"chat"`, `"openai"`, `"chatgpt"`, `"responses"`, `"codex"`, `"native"` and `"ollama"`. Under `"auto"` each request goes over the client's own protocol when the driver's server speaks it (Chat Completions otherwise) and falls back to the next one when the server answers 404, 405 or 501; an explicit value is always that protocol and never falls back. The full rules, the per-driver protocol lists and the fall back are in [drivers.md](drivers.md#choosing-the-protocol-api).

Upgrading: the old default was Chat Completions. `"auto"` still gives a Chat Completions client Chat Completions on every driver, but an Anthropic client now reaches vLLM 0.11.1 and later over `/v1/messages` and a Responses client reaches a server that has it over `/v1/responses`. Set `api: "chat"` on an upstream to keep Chat Completions for every client.

## Upstream `vertex` (not a converter setting)

`vertex` is set on an upstream for the Google Vertex AI driver, next to `url`, `apiKey` and `backend`, not in `settings`. It is an object with `project` and `region` (strings), and `credentials` (a service account or `authorized_user` key as an object, JSON text or file path), `accessToken` (a string), `getToken` (a function returning a token, or a promise of one) and `metadataServer` (`true` or a base URL) that choose how requests are authenticated. A value of the wrong type throws a `TranslatorError` with code `INVALID_CONFIG` when the translator is created. Without these keys the driver reads `ANTHROPIC_VERTEX_PROJECT_ID`, `GOOGLE_CLOUD_PROJECT`, `GCLOUD_PROJECT`, `CLOUD_ML_REGION`, `GOOGLE_ACCESS_TOKEN` and `GOOGLE_APPLICATION_CREDENTIALS` and gcloud's application default credentials file. The order, the gcloud commands that set each one up and the other behaviour are in [drivers.md](drivers.md#google-vertex-ai-claude).

## Amazon Bedrock upstream fields (not converter settings)

These are set on an upstream with `backend: "bedrock"` (or a `bedrock-runtime` URL), next to `url`: `region`, `accessKeyId`, `secretAccessKey`, `sessionToken`, `profile` (a profile of the AWS shared config files: access keys, a `credential_process`, an SSO login, a role to assume or a web identity) and `apiKey` for a Bedrock API key. Each is a non-empty string. When they are left out, the region comes from the URL's host name, then `AWS_REGION`, then `AWS_DEFAULT_REGION`, then the region of the profile used, and the credentials from `AWS_BEARER_TOKEN_BEDROCK`, then `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY` and `AWS_SESSION_TOKEN`, then the AWS credential chain (the `AWS_PROFILE` or `default` profile, the web identity of the environment, an ECS task role, an EC2 instance role; see [drivers.md](drivers.md#amazon-bedrock)); a `profile` setting comes before the environment's keys; `url` defaults to `https://bedrock-runtime.<region>.amazonaws.com`. The `sampling` setting becomes `additionalModelRequestFields` on a Converse call. Details are in [drivers.md](drivers.md#amazon-bedrock).

## Pool config (not a converter setting)

Failover and load balancing between upstreams that serve the same model are configured with the translator's `pool` key, not with `settings`: `strategy` (`failover`, `round_robin`, `least_busy`), `models` (strategy per model after aliases) and `backoff` (`base` and `max` in ms), `connectTimeout` and `headersTimeout` (ms), `healthInterval` and `healthTimeout` (ms, readiness probes). It is described in [server.md](server.md#endpoint-pools-failover-and-load-balancing). An invalid value throws a `TranslatorError` with the code `INVALID_CONFIG` when the translator is created.

## Effort levels and pinned aliases (not converter settings)

Which reasoning effort levels a model honours is configured with the translator's `efforts` key, keyed by the model name after aliases. A value is a list of levels (`minimal`, `low`, `medium`, `high`, `xhigh`, `max`) or `{ "levels": [...], "default": ... }`:

```json
{
	"efforts": {
		"GLM-5.3-Flash": ["low", "high", "max"],
		"other-model": { "levels": ["low", "high"], "default": null }
	}
}
```

For a model with a list, on an OpenAI-protocol upstream:

- a requested level in the list is sent as is, `max` and `xhigh` included, whatever `effortPassthrough` says;
- any other level snaps to the nearest one in the list (a tie goes to the higher level) and one warning is printed per message;
- a request that does not turn reasoning off and names no effort gets `default`: a level from the list, `null` to send nothing because the model has its own default, or, when `default` is left out, the level nearest to `medium`. The translator no longer sends `medium` for such a model;
- `none` and a disabled thinking mode are never changed.

A model without a list behaves as before: `max` and `xhigh` become `high` unless `effortPassthrough` is on, and a thinking request in `reasoning_effort` mode with no effort sends `medium`.

An alias can pin settings instead of only renaming the model: `"aliases": { "glm-flash-max": { "model": "GLM-5.3-Flash", "effort": "max" } }`. `effort` replaces the request's effort (it is mapped even when the `effort` setting is off) and then goes through the model's list. `thinking: false` turns thinking off and `thinking: true` undoes a client's `disabled`. A plain string alias works as before. See [server.md](server.md#aliases-that-pin-settings) for the models endpoint.

## Where settings come from

The vLLM driver derives some values from the detected server version (for example `reasoningField` and `thinkingBudget`), the `compatible` driver uses conservative defaults, and each upstream in the configuration can pin its own `settings`. The server layer documents the configuration file; this page covers the converter keys only.

## Examples

A text-only model behind vLLM 0.15, with Claude Code's deferred tools turned off at the client:

```json
{
	"settings": {
		"images": false,
		"reasoningField": "reasoning_content",
		"inlineSystem": "user",
		"toolSchema": "sanitize"
	}
}
```

Rejecting anything the translator cannot map instead of dropping it:

```json
{ "settings": { "unknownFields": "error", "documents": "error" } }
```
