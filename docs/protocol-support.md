# Protocol support matrix

This page lists how every Anthropic Messages feature maps to Chat Completions and back. It describes the converters in `src/api/convert/**` (the pure, I/O-free layer); transport, routing, detection and the server are covered in the decision register.

Two directions are covered:

- **A to O** (`convert.anthropic.messages.to.openai.chat.*`): an Anthropic client such as Claude Code talking to an OpenAI-style server such as vLLM. The request goes Anthropic to OpenAI, the reply goes OpenAI to Anthropic.
- **O to A** (`convert.openai.chat.to.anthropic.messages.*`): an OpenAI-style client talking to an Anthropic-protocol upstream. The request goes OpenAI to Anthropic, the reply goes Anthropic to OpenAI.

To keep the tables compact, each row names the file pair that implements the direction: in A to O, `request.mjs` under `anthropic/messages/to/openai/chat` and `response.mjs` / `stream.mjs` under `openai/chat/to/anthropic/messages`; in O to A, the mirror image.

## Status vocabulary

| Status      | Meaning                                                                                                             |
| ----------- | ------------------------------------------------------------------------------------------------------------------- |
| lossless    | The value crosses unchanged (possibly renamed).                                                                     |
| mapped      | A defined, reversible or near-equivalent translation exists.                                                        |
| best-effort | The translation approximates the meaning; behaviour depends on the server or model.                                 |
| dropped     | The value is removed. Silent when the field has no effect on the other side, otherwise recorded in `state.dropped`. |
| error       | The converter or the server rejects the request with an explicit error.                                             |
| n/a         | The concept does not exist in this direction.                                                                       |

Settings named in the last column are described in [settings.md](settings.md). Anything marked `unknownFields` becomes an error when `unknownFields: "error"` is set.

## 5. Errors

| Case                             | Result                                                                                                                                                                |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Upstream error                   | Returned in the client protocol's error shape, status mapped one to one (`retry-after` kept on 429).                                                                  |
| Context overflow from vLLM (400) | Anthropic `invalid_request_error` with `prompt is too long: <n> tokens > <max> maximum`, where `n` is prompt plus requested completion, so that Claude Code compacts. |
| Mid-stream error                 | Anthropic `error` event (A to O) or an error chunk plus `[DONE]` (O to A).                                                                                            |
| Translator errors                | `TranslatorError` renders as either protocol's error body (`toAnthropic()`, `toOpenAI()`).                                                                            |

Error type correspondence used by the converters: `400` and `invalid_request_error`, `503`/`529` and `overloaded_error`, `401` and `authentication_error`, `403` and `permission_error`, `404` and `not_found_error`, `413` and `request_too_large`, `429` and `rate_limit_error`, `529` and `overloaded_error`, everything else `api_error`.
